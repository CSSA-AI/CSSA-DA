## 背景

[rag-config.yaml](../../../app/core/config/rag-config.yaml) 的 system prompt 里有一句
「如果资料中没有答案,请说明资料不足,不要编造」。
[orchestrator.py](../../../app/services/rag/orchestrator.py) 里**没有**任何兜底:检索回
空、或者回五条不相关的东西,都原样交给 generator。所以这条行为**完全挂在那一行
prompt 上**。

而它在 v1 不是边缘情况,是主路径。知识库是 handbook + 微信文章,内测的人问的大多数
问题资料里根本没有。一个编得挺像的答案,比一个明显的失败更快让人不再提问 —— 而 v1
唯一要产出的东西就是「开始积累真实提问」。

改之前,没有任何测试会因为这条行为坏掉而变红:

- [test_chatgpt_generator.py](../../../tests/unit/test_chatgpt_generator.py) 把 OpenAI
  整个 mock 掉了,测的是构造参数,不是模型说了什么
- [chat_interactions.py](../../../app/services/chat_interactions.py) 会给每一行交互记下
  system prompt 的 sha256,**事后**查得到坏回答是哪版 prompt 产生的 —— 但**事前**没有
  任何东西告诉你这版 prompt 还拒不拒答

会静默弄坏它的改动很具体:删掉那一行、加一句「可以适当推测」、换模型或版本、改
`context.max_items` / `max_chars_per_item`。本次改动要做的就是让这些改动**有地方
变红**。

## 基础知识

### 一、契约测试:它证明什么、不证明什么

> 这一组讲「这是一种什么测试」—— 决定了后面所有取舍的尺度。

**从哪来。** 普通单元测试断言「输入 X,输出 Y」。生成模型没有唯一的 Y:同一个问题
两次回答措辞不同,temperature 0.3 下甚至内容也可能不同。于是常见的两条路都走不通 ——
逐字比对(永远红),或者 mock 掉模型(永远绿,测不到任何行为)。

**契约测试**走第三条路:不规定输出是什么,只规定输出**必须满足的性质**。这里的性质是
「资料里没有答案时,说资料不足,并且不给出资料外的具体事实」。任何满足它的措辞都算过。

**它守的是一类具体的改动,不是模型的平均水平。** 删掉「不要编造」、换模型、改上下文
形状 —— 这类破坏不微妙,20 条里会挂一片而不是挂一条,所以 20 条这个样本量够用。
反过来,**20/20 不等于幻觉率为 0**,只证明这一版没有明显破坏这条行为。它不是质量指标,
别拿它比较两个模型谁更好。

**为什么是发布关卡,不是 CI 测试。** 它要真调 OpenAI。钱不是问题(20 条 × gpt-4o-mini
一次一美分量级),真正的代价是非确定性:偶尔红的测试,最后都会被人加 `skip`,加了
`skip` 它就什么都不守了。所以不让它每次 push 都跑,而是**固定在几个会动到它的时刻
必须跑**(见 [什么时候必须跑](#什么时候必须跑))。这是 2026-08-10 在 roadmap 里定的,
本次照此实现。

**同理,挂了不能重跑到绿。** temperature 0.3 下一条用例挂了,说明这版配置在这个形状上
**有相当概率**编造 —— 这是发现,不是噪声。第一次运行挂的那条,采样 10 次挂 10 次。

### 二、负样本的形状:相关,但恰好没有答案

> 这一组讲「喂什么进去」—— 用例造错了,判据再严也测不出东西。

**朴素做法和它的问题。** 最省事的负样本是「问签证,给一段菜谱」。模型拒答这种题几乎
不会错 —— 上下文和问题毫无关系,说「资料里没有」是最自然的反应。它能过,但什么也
证明不了。

**线上真实的形状**是:检索回来的东西**看起来很相关**,讲的就是那门课、那个活动、那类
政策,只是恰好缺了被问的那一项。这正是模型最容易「顺手补一个」的地方 —— 它手里有
一堆相关的数字和名词,再加上自己训练时见过的知识。

所以 20 条用例全部按这个形状构造:

| 来源 | 条数 | 构造方式 | 例子 |
|---|---|---|---|
| handbook | 10 | 同一门课的其他几页都在,唯独删掉回答问题的那一页 | 问 ECON90033 的 prerequisite,给 Overview + Assessment + Dates,不给 Eligibility |
| 微信文章 | 10 | 讲对了事的那篇文章,里面本来就没写被问的细节(或删掉写了的那半句) | 问沙滩排球报名截止日,给活动预告 —— 时间地点费用都有,唯独没有截止日 |

其中 2 条用英文提问;有一条上下文放了两篇文章(同一周的两个活动预告),和检索真实
返回的样子一致。handbook 的 prerequisite / census date / 考核 / 教材 / 协调人,和微信
的打工时长 / 签证审理时间 / 落户政策,都是新生真会问、模型又「知道一点」的题。

**两个可机检的性质。** 「相关但无答案」如果只靠人看,迟早会有人改用例时改坏。所以
每条用例带两个字段,在每次 push 的单测里检查:

```yaml
- id: handbook-busa90500-census-date
  query: BUSA90500 的 census date 是哪天？最晚什么时候退课不算 fail？
  anchors:  [BUSA90500, May]        # 必须出现在上下文里 —— 这是「相关」
  withheld: [5 June, 26 June]       # 必须不出现在上下文和问题里 —— 这是「无答案」
  context:  [Overview, Eligibility, Assessment]   # 唯独没有 Dates and times
```

`withheld` 还有第二个用途:判定时回答里也不许出现它(见下一组)。

**为什么绕过检索。** 用例直接构造成 `SearchResult` 交给 generator,不走 retriever /
reranker。测的是**生成器的行为契约**,不受当前检索质量影响 —— 检索换了、库重建了,
这组测试的输入都不变。

**为什么冻结原文。** 上下文是从
[data/unimelb_subjects_2026.json](../../../data/unimelb_subjects_2026.json) 和
[data/wechat_articles_processed.json](../../../data/wechat_articles_processed.json)
逐字拷进 [refusal_cases.yaml](../../../tests/generator_contract/refusal_cases.yaml)
的,不是运行时去读。handbook 还要重抓(Data 0.1),如果测试跟着数据文件走,重抓一次
用例就悄悄变了,「这版比上版差」就无从说起。每段原文都截在
`max_chars_per_item` 以内,所以**存的就是模型看到的**。

### 三、判据:两条都要

> 这一组讲「怎么判」—— 全部是可执行的断言,不是人读输出。实现在
> [refusal.py](../../../app/services/rag/eval/refusal.py)。

**判据 1:回答里有拒答表述。** 「资料不足」「没有提到」「并未说明」「无法确定」
「does not mention」……一组正则,**故意放得宽**。模型说「资料不足」的方式太多,卡
措辞只会制造假失败。

**判据 2:回答里没有上下文之外的具体事实。** 这条才是关键。只判第一条是纸糊的 ——
模型完全可以先说一句「资料不足」,然后接一段编的:

```
资料不足。不过一般来说 census date 是 6月5日，需要先修 BUSA90499。
            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
            判据 1 通过;判据 2 抓到 "6月5日" 和 "BUSA90499" 不在上下文里
```

「具体事实」指能被核对的那一类:课程代码、链接、邮箱、日期、钟点、电话、金额、以及
其余一切数字。每一个都必须能在**证据**里找到。证据 =

- 模型**实际看到的**上下文 —— 截断之后的版本,被 `max_chars_per_item` 截掉的部分
  不算「看到过」;去掉 formatter 自己加的 `[资料 3]`、`检索排名: 3` 这类编号行,
  否则数字 3 就白白变成了「资料里有的」
- 加上问题本身 —— 正确的拒答常常会复述问题(「资料没有提到 BUSA90500 的……」)

**按值比较,不按写法比较。** 上下文写「31 March 2026」,回答写「3月31日」,是同一个
日期;上下文「14:00」,回答「下午2点」,是同一个钟点;「$1,200」和「1200」是同一个
数。复述上下文里的事实不能算编造,否则第一次运行就会满屏假失败。

**日期和钟点要整体比较,不能拆成数字。** 这是判据里最容易想错的一点。「6月5日」拆开
是 6 和 5,而几乎任何一段课程资料里都有 Week 5、Week 6。如果只检查数字,编出来的日期
永远能躲在别的数字后面。所以日期按 (月, 日)、钟点按一天中的第几分钟整体比对,
「7点」这种没写上下午的,两种读法任一在证据里就算有。

**`withheld` 兜住没有数字的那部分。** 判据 2 只认得带数字、带格式的事实。「需要被
Master of Finance 录取」没有数字,判据 2 看不见。每条用例把被删掉的那个答案(或模型
很可能凭记忆给出的那个答案)写进 `withheld`,回答里出现即失败。

**严与宽的分工。** 判据 1 宽、判据 2 严,是有意的:宽的那条负责不误伤正常拒答,严的
那条负责不放过编造。把严格放在判据 1(比如要求逐字出现「资料不足」)只会得到一堆
措辞不对的假失败,而对「先拒答再编」毫无办法。

### 四、判据本身也要被测试

> 这一组把前三组粘起来:用例和判据都是代码,而这组测试只有它们一样可信。

判据如果悄悄放过了「资料不足,但 census date 是 6月5日」,20/20 就一文不值。所以判据
有自己的单测([test_refusal_judge.py](../../../tests/unit/test_refusal_judge.py)),
逐条钉住:每一种偷带事实的方式都要被抓到,每一种合法的复述都不能被误判。

这不是形式主义。第一次真跑,20 条里挂的 3 条中有 **2 条是判据的错**:模型说的是
「资料中并没有**具体**列出所需教材」和「没有关于 BUSA90500 的 census date 和退课
截止日期的信息」,都是正确的拒答,但判据的正则一个漏了中间的副词,一个把「没有……
信息」之间的距离卡得太短。这两句原话已作为回归用例写进单测。

### 3. contract 测试

> 前置基础:[一、契约测试](#一契约测试它证明什么不证明什么)

[test_refusal_contract.py](../../../tests/generator_contract/test_refusal_contract.py):

- **marker** `generator_contract`,注册在 [pytest.ini](../../../pytest.ini)
- **默认不跑**:没有 `RUN_GENERATOR_CONTRACT=1` 时整个模块 skip —— 和集成测试的
  `RUN_INTEGRATION_TESTS=1` 同一个做法。它也不在 `tests/unit/` 下,所以
  `uv run pytest tests/unit -q` 和 CI 都碰不到它
- **生产配置原样**:只传 API key,model / temperature 0.3 / prompt / 上下文上限全部
  读 `rag-config.yaml`。**不为了稳定把 temperature 改成 0** —— 那测的是一个没人在跑
  的配置
- **真 key 在 import 时读**:[tests/conftest.py](../../../tests/conftest.py) 会在每个
  测试前后把 `OPENAI_API_KEY` 换成假的,所以 key 在收集阶段(fixture 还没跑)就取好。
  开了开关却没有 key,直接 fail 而不是 skip —— 一个悄悄 skip 的发布关卡等于没有
- **报告头带配置指纹**:[conftest.py](../../../tests/generator_contract/conftest.py)
  在输出第一屏打印

  ```
  generator contract: model=gpt-4o-mini temperature=0.3 prompt=sha256:9248b089e5c5 context=5x2000 chars
  ```

  贴进 PR 的结果因此自带「测的是哪版」。`prompt=` 用的就是
  `chat_interactions.prompt_version()`,和线上每一行交互记录的指纹是同一个值,可以
  直接对上

## 第一次运行发现了什么

**第一次:17/20。** 3 条失败里 2 条是判据的错(见
[基础知识四](#四判据本身也要被测试)),修掉后回判这次的答案是 19/20。剩下 1 条是真的:

```
问:持学生签证在澳洲打工，每两周最多可以工作多少小时？
给:一篇 2017 年讲打工权益的文章,删掉了「（比如说要求你每两周工作超过40小时）」这半句
答:持学生签证的国际学生在澳洲每两周最多可以工作40小时。
```

没有拒答,直接凭记忆给了一个**已经过时**的数字(现行是 48 小时)。这正是 issue 担心
的那一类:上下文讲的是对的话题,模型就把自己知道的填了进去。

**这不是偶然。** 同一条用例、生产配置,采样 10 次挂 10 次,其中 4 次还冠以「根据资料」。
于是改 prompt,每个版本同样采样 10 次:

| 版本 | 改了什么 | 该用例 10 次 |
|---|---|---|
| 原 prompt | —— | **0/10** 全部答 40 小时 |
| A | 加一句「即使你认为自己知道答案,也不要用资料以外的信息补充」 | **0/10** 照答 40 小时 |
| B | 要求每个具体信息都能在资料原文中找到;去掉「知识丰富」 | **0/10** 改为把资料里「兼职每周 38 小时」说成两周上限,10 次都冠以「根据资料」 |
| C | 点明「资料讲到相关话题,不等于回答了这个问题」 | **6/10** 挂的 4 次:直接答 40 小时;先说没提到、再「一般来说 40 小时」;两次算出 38 × 2 = 76 小时 |
| **D(采用)** | C + 可以建议去哪查,但不给答案本身;点名不许用「一般来说」「通常」「可以推测」从别处推算 | **10/10** |

几个值得记住的观察:

- **泛泛地说「不要用外部知识」没用**(A)。模型不觉得自己在用外部知识
- **要求「数字必须来自原文」会把编造换成张冠李戴**(B)。数字确实在资料里,只是回答的
  不是这个问题。判据 2 对此无能为力 —— 抓住它的是判据 1:这种回答没有拒答表述。
  两条判据缺一不可,这里有了实例
- **有效的是直接点破这个形状**(C/D):相关 ≠ 回答了。以及把「拒答之后再补一句」的
  常见句式点名禁掉

**会不会从此什么都拒答?** 这组测试本身回答不了 —— 一个永远说「资料不足」的 prompt
也能 20/20。所以换 prompt 前另做了一次正向对照(一次性脚本,未提交):把 9 条用例
被删掉的内容放回去,再加 5 条微信文章里直接有答案的问题,要求回答不含拒答表述、且
包含那个事实。原 prompt 和 D **都是 14/14**。

**最终:** prompt 指纹从 `sha256:a992902e83de` 变为 `sha256:9248b089e5c5`,连续三次
完整运行均 20/20。

## 已知边界

- **20/20 不是幻觉率。** 见 [基础知识一](#一契约测试它证明什么不证明什么)
- **判据看不见的东西**:没有数字的编造(编一本教材名、编一个办公室),除非它恰好在
  该条的 `withheld` 里;用中文数字写的事实(「十二学分」);**资料里有、但被安到了
  别的事情上**的事实 —— 后者只有在回答同时没有拒答表述时才会被判据 1 抓住(见 B 版本
  那一行)。这些需要读回答,`-rA` 就是为此
- **不测过度拒答。** 这组测试奖励拒答,一个什么都拒的 prompt 也能满分。这次靠一次性
  的正向对照兜住;把「有答案时要答」也做成可重复的用例,属于
  [Phase 3.2](../../roadmap/ROADMAP_rag.md#32-其他契约) 一类的后续工作
- **不测「资料过期」。** 上下文里**有**答案、只是过期了(一篇 2019 年的招聘推文),
  模型照着答不算编造。这是 [ROADMAP_data.md](../../roadmap/ROADMAP_data.md) 里记录的
  已知风险,不在本测试范围
- **只走 `generate_text`,单轮。** `/v1/chat` 走的是它;`stream_text` 和带
  `chat_history` 的多轮没有覆盖
- **只测一个模型。** 用例和判据是模型无关的,但「20/20」只对报告头那行写的配置成立
